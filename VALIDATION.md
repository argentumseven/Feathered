# Release verification

The release runner now reconciles the collected test IDs with setup, call and
teardown records from each pytest subprocess. A zero subprocess exit is necessary
but insufficient: missing, stale, incomplete or contradictory evidence fails the
gate. Normal pytest reporting and shutdown remain enabled.

## Per-run results

The authoritative result is generated by the runner, rather than maintained as a
handwritten test count:

- `validation/release-gate/SUMMARY.md`: human-readable result, actual outcome
  counts, commit, source-tree digest, Python/pytest versions and environment.
- `validation/release-gate/summary.json`: every final test outcome, allowed skip
  reason, batch reference and subprocess exit/signal/timeout result.
- `validation/release-gate/collection.json` and `batch-NNN.json`: collected IDs,
  collection problems, deselections, and individual setup/call/teardown reports.
- `validation/release-gate/*.log`: normal pytest failure explanations and output,
  retained even when a subprocess crashes or times out.

The source-tree digest includes source changes beyond the named commit. Generated
validation evidence is outside source-manifest scope, so writing a report does
not change the source identity it describes. CI uploads the reports on failure
as well as success. Windows and the required Debian job verify the same Git SHA
before production publication is eligible.

## Platform expectations

On Linux, the full corpus must pass with Tk/Xvfb and the fixture tools available.
No skip is accepted. The required Debian native-conformance job now runs this
complete batched gate in addition to its existing required integration slice.

Windows may record only the exact file/reason combinations listed in
`release_test_runner.WINDOWS_SKIPS`: missing dpkg fixtures, the named Bash checks,
and the symlink-capability check. These are reported as skips, never as passed or
executed tests. Missing Tk/display, unrelated skips, collection skips, deselection,
xfail and xpass fail the gate. Every permitted Windows skip must execute in the
required Linux full-corpus job; production publication requires both jobs.

## Reproduction

```bash
python -m mypy
python check_host_contracts.py
ruff check .
python check_installer_syntax.py
python verify_source_checksums.py
FEATHERED_USE_XVFB=1 python release_test_runner.py
```

On Windows, omit `FEATHERED_USE_XVFB=1`. The runner defaults to a 300-second
collection/batch deadline; `--timeout SECONDS` overrides it explicitly. A timeout
fails the gate and stops the child process tree. `--report-dir PATH` selects a
different evidence directory. Test IDs are passed in JSON and source paths in a
pytest argument file, avoiding command-line limits without omitting parameters.

## Scope of local validation

The follow-on batch implements instruction items 2–5: credential-safe display
with source URLs visible, strict decoding of recognized spec fields and runtime
preparation inputs, partial-outage recovery, shared release-knowledge ownership,
and bounded UI event processing with incremental query coordination. Each
behavioral repair has focused regression evidence in `validation/batch25/`;
the complete final-tree result remains `validation/release-gate/SUMMARY.md`.
Malformed specs formerly accepted by truthiness are intentionally rejected;
valid older specs and incomplete drafts remain supported. See
`BACKGROUND-REFRESH.md` for cache ownership, cancellation and migration scope.

The new heartbeat test demonstrated queue starvation under a synthetic progress
burst. It is a reproduction of that bounded scenario, not a claim that every
historical UI hang had the same cause. No tests are deliberately deselected in
the delivered full release gate. Diagnostics during development included a
headless focused run and a display-harness setup failure; those are not counted
as GUI validation.

The implementation review uses Linux, Python 3.12.14, pytest 9.1.1 and Tk/Xvfb.
Mypy and Ruff use the configured versions, 1.18.2 and 0.14.2. Local execution does
not establish Windows execution, Authenticode signing, frozen production builds,
staged gpgv behavior, native package-manager oracle acceptance or live upstream
availability. Those checks were not performed for this batch. The
existing CI requirements for native conformance and signed production remain in
place; a workflow definition is not evidence that its remote job has run.

Item 1 changed only release verification. The follow-on batch changes application
input validation and discovery/event handling; it does not change package
resolution, bundle layout, stored repository credentials or transport identity.
